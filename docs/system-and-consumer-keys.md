# System And Consumer Keys

System and consumer API keys are generated by Moira, hashed with Argon2id, looked up by prefix, and fingerprinted for audit. Raw keys are returned only to the request that wins an atomic create or rotate command.

Create/rotate response:

```json
{
  "resource": {},
  "secret": "moira_sys_...",
  "secret_retrievable": true
}
```

Read and idempotent replay responses set `secret_retrievable: false` and return `secret: null`. Create replays retain `201`, and rotate replays retain `200`; they never recover the original raw key. If the winning response is lost, rotate with a new `Idempotency-Key`.

Reusing a key for different request input returns `409 idempotency_conflict`. A bounded wait for the winning transaction returns `409 idempotency_in_progress`. The raw key is excluded from idempotency records and audit metadata.

System key endpoints use `/api/v1/admin/system-keys`; consumer key endpoints use `/api/v1/admin/consumer-keys`. Consumer keys must be bound to one application.

Required scopes:

- Read/list/get: `moira:system-keys:read` or `moira:consumer-keys:read`
- Create: `moira:system-keys:write` or `moira:consumer-keys:write`
- Rotate: `moira:system-keys:rotate` or `moira:consumer-keys:rotate`
- Revoke/delete: `moira:system-keys:revoke` or `moira:consumer-keys:revoke`

Bootstrap the first root system key with:

```bash
cargo run -- bootstrap-system-key
```
