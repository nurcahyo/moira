- [ ] Bound stale-JWKS retention in time (#95) — source: plans/03-security-hardening.md — `src/security/auth.rs` serves a retained cache entry on *any* fetch failure with no maximum staleness, and neither `entries` nor `locks` is ever evicted. The right availability call short-term, but it converts "DoS the IdP's JWKS endpoint" into "a compromised signing key can never be rotated out". - [ ] Retire the legacy-hash acceptance window — source: plans/03-security-hardening.md — plan 03 adds `idempotency.accept_legacy_hashes` (default `true`). - [ ] Redact `Debug` on pepper-bearing types (#95) — source: plans/03-security-hardening.md — `IdempotencyHasher` derives `Debug` over `pepper: Vec<u8>`, `AdminCommandRunner` derives `Debug` while holding it, and `IdempotencySettings` derives `Debug` over `pepper_base64`. **No active leak today** — a reviewer grepped every `{:?}`/`?state`/`?settings` path reaching them and found none — but `src/application/conversation.rs` already uses `format!("{spec:?}")` in the same area, so the idiom is live. - [ ] Sweep expired rows on the public idempotency ledger (#92) — source: plans/03-security-hardening.md — the admin transaction sweeps both key hashes before lookup; the public path has none. `claim_idempotency` does `on conflict do nothing` then reads with `expires_at > now()`, so when the conflicting row is expired the read returns `None` and the caller gets a **permanent** `409 execution_in_progress` for that key. - [x] Document that `CatchPanicLayer` does not cover streaming-body panics — source: plans/03-security-hardening.md — tower-http wraps only `inner.call(req)` and the response future, not the response body.
